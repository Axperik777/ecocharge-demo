# Три приложения ECO CHARGE

## Схема

```text
Лендинг A ─┐
Лендинг B ─┼──→ Один клиентский кабинет ←──→ Одна CRM
Лендинг C ─┘        /login/, /client/          /team/
                                             ├─ FTD: /crm/
                                             └─ Администратор: /staff/
```

Один репозиторий, три точки сборки и три пакета публикации. Общие бренд, переводы и модель данных остаются общими. Копировать весь проект на каждый рекламный домен не нужно.

| Часть | Точка сборки | Что менять |
| --- | --- | --- |
| Публичный сайт | `apps/website/app.cjs` | Страницы `src/site-pages.cjs`, тексты и секции `src/`, стили `dist/site.css`, поведение `dist/site.js` |
| Личный кабинет | `apps/account/app.cjs` | Клиентский интерфейс, вход, регистрация; общий шаблон `src/portal.html` |
| CRM команды | `apps/crm/app.cjs` | Простой FTD: `apps/crm/index.html`, `dist/crm.js`, `dist/crm.css`; расширенный администратор: общий шаблон портала |

Регистрация использует общий публичный шаблон. Кабинет администратора и клиента пока используют общие компоненты портала. Изменение общей модели или перевода требует проверки всех трёх частей; отдельный пакет публикации не перезаписывает файлы других приложений.

## Сборка

```sh
# Текущая общая публикация GitHub Pages
node build.cjs
node validate.cjs
node --test tests/*.test.cjs

# Только HTML нужного приложения
node build.cjs --app website
node build.cjs --app account
node build.cjs --app crm

# Изолированные пакеты для отдельного хостинга
node scripts/export-app.cjs --app website --config config/separate-domains.example.json --variant stations
node scripts/export-app.cjs --app account --config config/separate-domains.example.json
node scripts/export-app.cjs --app crm --config config/separate-domains.example.json

# После экспериментальных сборок вернуть стандартный dist для GitHub Pages
node build.cjs
```

Экспорт создаёт новую папку `release/<app>-<variant>-<timestamp>/`. Публикуется её содержимое. Папки `release/` не входят в Git. Экспорт сайта не содержит страницы и скрипты портала/CRM. Статические фотографии, шрифты и библиотеки копируются в каждый пакет; браузер загружает только необходимые странице файлы. `app-manifest.json` фиксирует приложение, маршруты и настройки.

Без локальной командной строки: GitHub → **Actions → Export one application → Run workflow**. Выберите приложение, профиль первого экрана и файл конфигурации. По завершении скачайте пакет из Artifacts. Этот workflow только собирает пакет и не меняет текущий сайт. `config/github-pages.json` направляет ссылки на существующий общий кабинет GitHub Pages; для своих доменов создайте отдельный файл конфигурации.

В файле конфигурации задаются `websiteBase`, `accountBase`, `crmBase` — полные базовые URL с завершающим `/`. Пустые значения означают текущий домен и базовый путь. Для размещения в подпапке указывается и она. Домены `.example` в примере — шаблоны, замените их своими перед публикацией. Новые домены и DNS этим кодом не создаются.

## Варианты лендинга

В `apps/website/variants.json` подготовлены 6 вариантов первого экрана: `main`, `stations`, `how-it-works`, `documents`, `guided`, `mobile`. Это разные заголовки и подзаголовки на общей структуре, а не шесть отдельных полноценных воронок. Их можно независимо развивать и публиковать. Все ведут на один `accountBase`.

В переход передаются только метки: UTM, `fbclid`, `gclid`, `landing_id`, `landing_host`, `lead_route` и язык. При регистрации первый источник сохраняется в карточке клиента. Баланс, пароли и персональные данные через URL не передаются. Изменение домена само по себе не исправляет слабый оффер или низкую конверсию; варианты требуют измерения на реальном трафике.

## FTD

Вход команды — `/team/`.

- `ftd / ftd1` открывает `/crm/`: пополнить, списать, изменить имя/email/телефон/заметку.
- `admin / admin1` открывает `/staff/`: планы, станции, заявки, сообщения и настройки. Отсюда есть ссылка на простой FTD-экран.
- `lox / lox1` — клиент через `/login/`.

Для изменения баланса нужны сумма и причина, затем подтверждение с балансом до/после. История сохраняет сотрудника, время и причину. Пополнение по заявке подтверждает её один раз. Ручное пополнение записывает подтверждённый учебный платёж. Списание не отправляет деньги клиенту и не меняет правило вывода раз в 4 дня. Зарезервированные выводы защищены от списания. Устаревшее подтверждение из другой вкладки отклоняется.

Комиссии для новых стартовых планов нет: к оплате и зачислению $250 / $500 / $800. В незавершённых старых заявках комиссия убирается; завершённая история сохраняется.

## Что работает в текущем демо

На GitHub Pages сайт, ЛК и CRM имеют разные маршруты, но один origin. Их данные синхронизируются между вкладками **одного браузера**. Предусмотрен один связанный учебный клиент, а не реальная многопользовательская CRM.

Для отдельного рекламного домена экспортируйте сайт с адресом центрального ЛК. В демо ЛК и CRM должны оставаться на одном origin (протокол, домен и порт), иначе у них будут разные хранилища. Их пакеты можно объединять на одном хосте; shared-файлы должны относиться к одной версии.

## Для настоящей эксплуатации

Нужны общая серверная база/API, отдельные учётные записи, права на сервере, журнал операций на сервере и платёжный провайдер с подтверждением платежей. После этого ЛК и CRM могут работать на разных поддоменах и устройствах. Текущий вход — навигационная проверка демо, не защита финансовых операций. Обработки реальных платежей и общей базы здесь нет.
